# Разведочный анализ сетевого трафика для выявления признаков кибератак

**Дисциплина:** Программные инструменты анализа данных в задачах информационной безопасности

**Выполнил:** Татарнев Павел Павлович

**Группа:** РИ-431001

## Описание проекта

Проект посвящён разведочному анализу сетевого трафика (Exploratory Data Analysis, EDA) для исследования признаков сетевых атак.

Цель работы – изучить характеристики нормального и атакующего трафика, выявить статистические закономерности и определить возможные проблемы подготовки данных для последующего обучения модели машинного обучения.

Задача машинного обучения – бинарная классификация:

- `0` – нормальный сетевой трафик.
- `1` – трафик, связанный с атакой.

## Набор данных

Используется **UNSW-NB15**, разработанный Университетом Нового Южного Уэльса (Австралия).

[Официальный источник датасета](https://research.unsw.edu.au/projects/unsw-nb15-dataset)

Для исследования выбрана обучающая выборка `UNSW_NB15_training-set.csv`, содержащая 175 341 запись и 45 столбцов.

Датасет автоматически загружается при выполнении ноутбука, если файл отсутствует в рабочей директории.

## Содержание исследования

- Постановка бизнес-задачи и ML-задачи.
- Выбор и обоснование метрик Recall, Precision и FPR.
- Исследование структуры и качества данных.
- Анализ распределения классов и категорий сетевых атак.
- Исследование протоколов, продолжительности соединений и объёмов трафика.
- Корреляционный анализ сетевых признаков.
- Выявление потенциальных ограничений датасета.
- Рекомендации по предобработке данных.

## Основные результаты

В ходе исследования установлено:

- Атакующий трафик составляет 68,06% обучающей выборки.
- После исключения `id` обнаружено 67 601 повторение записей.
- Признак `sttl` имеет корреляцию Спирмена +0,732 с целевой переменной.
- Некоторые значения сетевых протоколов сильно связаны с определёнными классами.

Выявленные закономерности могут быть обусловлены особенностями лабораторного датасета. Их применимость к реальным корпоративным сетям требует дополнительной проверки.
